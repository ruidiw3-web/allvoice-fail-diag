# 趣丸千音 · 原剧管理页复刻 + 任务失败诊断优化

在线 Demo：https://ruidiw3-web.github.io/allvoice-fail-diag/

## 这是什么

以「专业 AI 产品经理」体验 [趣丸千音 allvoicelab.cn](https://www.allvoicelab.cn) 视频翻译功能后，
针对 **「任务处理失败后界面不给出任何失败原因」** 这一 UX 问题做的一个小而具体的复刻 Demo。

- **复刻保真**：页面不是手写重现的，而是抓取真实工作台「原剧管理」页的 DOM 快照 + 全量 CSS 内联重建，
  字体、SVG 图标、Element Plus 表格结构、列宽比例、状态胶囊样式与原站一致；
  在 1440 视口下与原产品逐像素对齐（剧名 190 / 状态 277 / 提取方式 377 … 创建时间 877）。
- **数据真实**：失败行的诊断字段取自真实失败任务（`drama_understanding_status=500`、`review_msg` 为空、
  `proofreading_block_reason="第1集：整剧说话人匹配待处理"`），没有编造失败原因。

## 问题

原产品对失败任务只显示两个词：「处理失败」「任务终止」。

- 不显示卡在哪个环节、什么错误码、什么时候失败；
- 没有任务详情页（点剧名 / 缩略图 / 双击 / 右键都不跳转）；
- 唯一入口是状态胶囊里的 ⟳，只问「确认是否失败重试？」，不说重跑哪一步、是否重复扣积分；
- 「导出 / 校对」置灰且悬停无任何解释；
- 但产品其实**已经记录了** `drama_understanding_status`、`review_msg`、`proofreading_block_reason`。

所以这个优化的本质不是「增加能力」，而是**把已有的信息显示出来**——风险低、可立即落地。

## 优化内容

在失败行下方加一条诊断带，并提供二级入口：

1. **失败定位**：阻塞环节 / 服务端状态 / 已产生产物 / 影响范围
2. **本次费用**：已扣 56 积分（余额 68 → 12）、重试是否重复扣费
3. **处理到哪一步**：六步进度条，哪一步中断一眼可见
4. **可以做什么**：仅重跑失败环节（推荐）/ 换一版片源 / 提交诊断给产运
5. **原始诊断信息**：面向产运和技术的字段明细
6. 重跑时进度条原地替换诊断带，完成后状态胶囊转绿、擦除状态转成功、导出解锁、产物体积出现

## 怎么玩

- 底部中央 **「优化后 / 优化前」** 切换：切到「优化前」即原产品原样，可做前后对照
- 点失败行右侧的 **「查看诊断」**（或状态格第二行的入口）打开右侧抽屉
- 点 **「仅重跑失败环节」** 走一遍重跑流程（含不重复扣费的确认弹窗）

## 技术说明
